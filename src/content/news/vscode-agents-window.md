Visual Studio Code 1.120 では、AI エージェントを複数のプロジェクトで動かすための Agents window が Stable 版でも preview として使えるようになりました。

Web サイト運用では、記事作成、サービスページ更新、レビュー、デプロイ確認が別々の作業になりがちです。Agents window は、こうした作業をプロジェクト単位で見渡しながら進めるための入口になります。

## 複数の更新を同時に扱いやすくする

Agents window は、通常のエディタとは別に、エージェント向けの作業画面を用意する考え方です。
記事追加、設定変更、ドキュメント整備のように性質が異なる作業を、セッション単位で分けて追跡できます。

小さな会社サイトでも、ニュース更新とサービスページ追加が同じ日に重なることがあります。
作業単位を分けて進められると、どの変更がどの PR に入ったのかを確認しやすくなります。

## Web 担当者にとっての価値

重要なのは、AI が動くことそのものではなく、更新後に確認できる状態まで短く進められることです。
Agents window では、変更内容を見直す、不要な変更を破棄する、基準ブランチと同期する、といった作業が画面上で扱いやすくなっています。

このサンプルリポでは、ニュースやサービスページを Markdown として追加し、`pnpm verify` と Vercel Deploy Preview で確認する流れを採用しています。
エージェント向けの作業画面が整うほど、URL と深掘りポイントを伝えるだけで更新を始める運用に近づきます。

## 導入時に見るべきポイント

まずは、更新対象を小さく分けることをおすすめします。
たとえば「ニュース 1 件」「サービスページ 1 件」「SEO レビュー 1 件」のように、PR の単位を明確にします。

そのうえで、[AI コンサルティング](/services/ai-consulting) や [Web 制作](/services/web-development) のような運用支援と組み合わせると、社内の Web 担当者が確認しやすい更新フローを作れます。
